# 15: Rank triage safety (states, deadlines, focus count, quote hygiene, fetch pacing)

**What to build:** Stop `rank-jobs` from quietly discarding live postings. Four terminal fates (fetch failure, location veto, language veto, real past deadline) currently all write `status: "expired"` (`lib/rank.ts:237,255,281,294,311`); free-text deadline phrases are trusted over stored values; focus non-matches vanish without a count; fetched-page quotes enter host-visible markdown raw; and up to 20 escalating fetches run sequentially. All small, all here, none shared with other tools — hence its own issue rather than riding 12 or 14.

- [ ] Split the terminal states and pin the retry policy per state, with the server staying stateless (all retry memory travels host-side in `stateUpdates`, never in server memory):
  - `ranked`: rests by default; re-scored only with `all: true` (unchanged).
  - `expired` (deadline genuinely past): terminal; never fetched again; the host may drop the row.
  - `unavailable` (fetch failed): retried on later runs but bounded — `stateUpdates` carries `lastAttemptDate` plus `attemptCount`, and the tool skips the re-fetch (emitting a note instead of burning the four-step escalation) once attempts reach 3 or the last attempt is under 3 days old; both bounds are named constants. A permanently dead URL must not be escalated forever.
  - `excluded` with a `reason` (vetoes): re-scored only when the profile changed. The tool cannot see profile changes, so the protocol is hash-based: the server computes a deterministic `profileHash` (canonical JSON of the resolved profile, sha1) and emits it in `stateUpdates`; `RankItem` gains an optional `lastProfileHash`, and an excluded item is re-scored if and only if the stored hash differs from the current one. Document the host flow (persist hash → send back → mismatch triggers re-evaluation).
