# 18: Tailor audit and gate (recombination, gate input, dropped content, compile flags, language fit)

**What to build:** Close the holes in the drafting trust chain in `lib/tailor.ts` (and one flag in the emitted compile commands). The word-level audit, the gateless input, the silent bullet caps, the shell-escape posture, and the headings-only translation are all here; the shared-matcher and regex carry-overs stay in issues 12 and 16.

**Blocked by:** 02-tailor-cv-cover-letter.

**Status:** done (commit: feat issue-18; full suite green including the former tailor-cover drift, fixed via lexicon "here")

- [ ] Recombination-proof the audit: `auditClaim` passes any claim whose content words each appear somewhere in the union, so scattered words reassemble into ungrounded claims ("Led Kubernetes migration" from three separate sources), and short numbers/years skip the audit entirely (the 4+ character rule). Add a numbers-and-dates check (every numeral in generated prose must appear in the union), and scope gap/requirement names to explicitly bridging slots: a gap name may appear only inside an "adjacent to X / new to me" template, and the audit verifies those words against the bridging slot rather than the whole union. (Nuance for the agent: the CV union carries no requirement names — CV labels are profile-sourced by construction — so the recombination risk concentrates in generated combinations and unaudited numerals; the cover union does carry requirement names, where the slot rule bites hardest.)
- [ ] Gate input on the drafting tools: both builders take only `postingText`, so they draft for postings `evaluate-job` failed. Accept an optional `evaluation` summary (verdict plus gate results, same stateless-contract shape as issue 14: the host passes it, the server holds nothing), refuse on FAIL, and warn loudly when it is missing — drafting blind must be a visible choice, never the default. Third consumer: `planInterviewPrep` (`PrepInput` carries no evaluation) — prepping for a gate-failed posting is pure waste; same optional-summary, refuse-or-warn shape.
- [ ] Visible cuts: the `[5, 3, 2]` bullet caps silently discard content, as does the over-budget cutting order. Return `droppedBullets` (role plus text) with the result so the host can show what was left out; the renderers surface the list.
- [ ] Compile-command hardening (small test): stock commands run without `--no-shell-escape`; content escaping neutralizes hostile text in fields, but the command line is the real boundary. Add the flag to the stock `lualatex`/`xelatex` commands (custom-template commands stay caller-owned and get a warning note), plus a hostile-posting fixture (`\`, `{`, `%`, `\directlua` strings in company, role, and requirement text) asserting clean compilation-surface output. (Note: `cover.cls` uses `\fontspec`, which requires XeTeX — keep `xelatex` for the letter; harden, don't switch engines.)
- [ ] Language-fit warning (small test): `cvLanguage` translates headings only while the body stays profile-language, and the CV input does not even accept a posting language (the letter's `postingLanguage` exists; the CV has no counterpart). Accept the posting language on the CV path and warn when it differs from `cvLanguage` (e.g. German posting, English body under German headings) so the mismatch is a decision, not an accident. Same warning on the letter path: `postingLanguage` changes structure and closing only, while the audit, stopwords, and bridging templates are English-only — warn on mismatch and state the English-only limitation instead of silently applying English machinery to non-English text. Same again for portal-fields: same `auditClaim`/stopword machinery, forms in another language misfire identically.
- [ ] `BUILDER_LEXICON` credential test: assert the framing-word allowlist contains no credential or skill nouns — it may only hold meta-commentary, so any future addition that smuggles a claim word fails loudly.
