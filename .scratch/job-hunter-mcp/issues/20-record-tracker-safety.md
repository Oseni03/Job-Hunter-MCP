# 20: Record tracker safety (injection, round trip, matching, stale writes)

**What to build:** Harden the tracker ledger in `lib/record.ts` where it meets hostile input (posting-derived cells), multi-line data, near-duplicate rows, and concurrent writers. Note on numbering: this was proposed as 19, but `19-cover-letter-safety.md` already exists — hence 20. Pure planner changes; the host-owns-writes contract is unchanged.

**Blocked by:** 03-record-application.

**Status:** done (commit: feat issue-20; full suite 430/430 green, golden 26 pass)

- [ ] Formula-injection neutralization with a hostile fixture: company and role come from postings and the CSV is opened in Excel/Sheets, where a leading `= + - @` executes. Neutralize those leading characters on write (leading-`'` convention) and specify the round trip precisely — matching and re-serialization must account for the prefix so a neutralized cell still matches, refreshes, and never double-prefixes. Fixture: company `=CMD|'/C calc'!A0` (plus `+`, `-`, `@` variants) through append → match → update, asserting inert cells and stable matching.
- [ ] Newline round-trip fix with a fixture: `serializeCsvLine` quotes newline-bearing fields, but the reader splits on EOL first and parses line by line — a multi-line field returns as broken rows on the next run. Either strip newlines from all written fields or parse the input as whole-text CSV; fixture with a newline-bearing role must survive append → re-read → update unchanged.
- [ ] Smarter matching without substrings: "Acme" vs "Acme Ltd" (or suffixed role variants) appends duplicates today under exact lowercased equality. Match on `postingUrl` first where present (the source column exists), then fall back to normalized company/role (lowercased, punctuation stripped, legal suffixes — Ltd, Inc, GmbH, … — removed); matching stays exact within the normalized form, so the substring-free property survives. Fixture: second application to the normalized-same pair updates instead of appending.
- [ ] Stale-write protection, stateless: full-file in/out means a host write after an interleaved edit (manual fix, second session) silently loses data. Return a hash of the input `trackerText` with the plan; the host writes only if the file still matches, making both overwrites and double-appends on stale input detectable. No server state — the hash travels with the plan, same pattern as the profile-hash protocol in issue 15.
- [ ] Multiple open matches (small): first open match wins silently today — emit a note naming the count when more than one exists, so the host can see the ledger needs deduplication.
- [ ] Slug-as-path lock-in (small): `archiveFile` embeds posting-derived text; assert by construction plus fixture (`../` in the company name) that `makeJobSlug` output allows only `[a-z0-9_-]` with no dots or slashes — the `slugify` map (non-alphanumerics to hyphens, trim, hash fallbacks) should already guarantee this; the test exists to keep it guaranteed.
- [ ] Host-passed date (minor): `today` defaults to the server clock (UTC day), which is a day off near midnight for other timezones. The `today` override already exists — document host-passed date as the norm and have the prompts supply it, so the recorded date is the user's day, not the server's.
